# 필요 개념 정리

UI/UX 실습을 진행하기 전에 알아야 할 핵심 개념을 정리합니다.

---

## 1. UI vs UX

| 구분     | UI (User Interface)            | UX (User Experience)                             |
| -------- | ------------------------------ | ------------------------------------------------ |
| **의미** | 사용자가 보는 화면·요소        | 사용자의 전체 경험                               |
| **관점** | 시각적, 인터랙션               | 사용 목표, 감정, 맥락                            |
| **예시** | 버튼 색상, 폰트 크기, 레이아웃 | "로그인 절차가 복잡하다", "목적지를 빨리 찾았다" |

> **핵심**: 좋은 UI는 좋은 UX의 일부입니다. 둘은 함께 고려해야 합니다.

---

## 2. 디자인 시스템 (Design System)

### 정의

디자인 시스템은 **재사용 가능한 컴포넌트**와 **디자인 토큰**을 정의한 규칙 모음입니다.  
일관된 브랜드·경험을 유지하면서 효율적으로 제품을 만드는 데 사용합니다.

### 구성 요소

| 요소              | 설명                                           | 이 프로젝트 예시                    |
| ----------------- | ---------------------------------------------- | ----------------------------------- |
| **색상**          | primary, background, muted 등 의미별 색상 정의 | `variables.css`의 `--color-primary` |
| **타이포그래피**  | 폰트, 크기, 줄 간격                            | `--font-size-base`, `--font-family` |
| **간격(Spacing)** | 여백 기준 값                                   | `--spacing-md`, `--spacing-lg`      |
| **컴포넌트**      | 버튼, 카드, 입력 필드 등                       | `components.css`                    |
| **아이콘/이미지** | 사용 규칙                                      | SVG 인라인, aria-label 사용         |

### 디자인 토큰 (Design Token)

디자인 토큰은 **색상·간격·타이포 등 원자 단위 값**을 변수로 정의한 것입니다.

- **장점**: 한 곳만 바꿔도 전체 UI에 반영
- **예시**: `--color-primary`를 변경하면 primary 버튼·링크 색이 모두 바뀜

## 3. 반응형 디자인 (Responsive Design)

### 정의

하나의 레이아웃이 **화면 크기에 따라 자동으로 최적화**되도록 하는 방식입니다.

### 브레이크포인트 (Breakpoint)

화면 너비에 따른 전환 시점입니다. 이 프로젝트 기준:

| 구분     | 너비         | 특징           |
| -------- | ------------ | -------------- |
| 모바일   | ~767px       | 1열, 터치 우선 |
| 태블릿   | 768px~1023px | 2열 그리드     |
| 데스크톱 | 1024px~      | 3~4열 그리드   |

### 모바일 퍼스트

작은 화면을 먼저 디자인한 뒤, 큰 화면용 스타일을 추가하는 접근법입니다.

---

## 4. 접근성 (Accessibility)

### 정의

**모든 사용자**가 동일하게 이용할 수 있도록 하는 설계입니다.  
시각·운동·인지 장애, 키보드만 사용하는 환경 등을 고려합니다.

### 핵심 원칙 (WCAG 4가지)

1. **인지 가능**: 텍스트·이미지·색상 대비 등 정보를 인지할 수 있어야 함
2. **조작 가능**: 키보드, 마우스, 터치 등으로 조작할 수 있어야 함
3. **이해 가능**: 내용과 조작 방법이 이해 가능해야 함
4. **견고함**: 다양한 브라우저·보조 기술에서 안정적으로 동작해야 함

### 실무 체크 포인트

| 항목            | 체크 내용                                           |
| --------------- | --------------------------------------------------- |
| **대체 텍스트** | 이미지에 `alt` 제공                                 |
| **색상 대비**   | 텍스트와 배경 대비 4.5:1 이상                       |
| **터치 타겟**   | 버튼·링크 최소 44x44px                              |
| **포커스**      | 키보드 포커스가 보이도록 스타일 지정                |
| **시맨틱 HTML** | `header`, `nav`, `main`, `footer` 등 구조 태그 사용 |

## 5. 유저플로우 (User Flow)

### 정의

사용자가 **특정 목표를 달성하기 위해 거치는 단계**를 순서대로 표현한 것입니다.

### 예시: "강의 수강 신청" 플로우

```
메인 → 강의 목록 → 강의 상세 → 장바구니 → 결제 → 수강 시작
```

### UX 관점에서 보는 것

- **단계 수**: 불필요한 클릭·입력이 있는지
- **피드백**: 작업 후 사용자에게 충분한 안내가 있는지
- **오류 처리**: 실패 시 복구·재시도가 가능한지
- **빈 상태/로딩**: 데이터가 없을 때, 로딩 중일 때의 경험

---

## 6. 컴포넌트 (Component)

### 정의

**재사용 가능한 UI 단위**입니다. 버튼, 카드, 입력 필드, 모달 등이 해당합니다.

### 상태(State)

컴포넌트는 상황에 따라 여러 상태를 가질 수 있습니다.

| 상태     | 설명             | 예시                     |
| -------- | ---------------- | ------------------------ |
| Default  | 기본 표시        | 일반 버튼                |
| Hover    | 마우스 오버 시   | 배경색 변화              |
| Focus    | 키보드 포커스 시 | 테두리/윤곽선            |
| Disabled | 비활성화         | 흐리게, 클릭 불가        |
| Loading  | 로딩 중          | 스피너, 비활성화         |
| Error    | 오류             | 빨간 테두리, 오류 메시지 |

## 7. 시맨틱 HTML

### 정의

내용의 **의미**를 나타내는 HTML 태그를 사용하는 것입니다.  
화면은 비슷해 보여도, 검색 엔진과 스크린 리더가 구조를 더 잘 이해할 수 있습니다.

### 주요 태그

| 태그        | 용도                          |
| ----------- | ----------------------------- |
| `<header>`  | 페이지/섹션 상단 (로고, 네비) |
| `<nav>`     | 내비게이션                    |
| `<main>`    | 본문 내용                     |
| `<section>` | 주제별 섹션                   |
| `<article>` | 독립적인 콘텐츠               |
| `<footer>`  | 페이지 하단                   |
| `<button>`  | 클릭 동작                     |
| `<a>`       | 링크 이동                     |

## 8. CSS 변수 (Custom Properties)

### 정의

`--변수명: 값;` 형태로 **재사용 가능한 값을 정의**하는 CSS 기능입니다.

### 사용법

```css
/* 정의 */
:root {
 --color-primary: #1a1a2e;
 --spacing-md: 1rem;
}

/* 사용 */
.button {
 background-color: var(--color-primary);
 padding: var(--spacing-md);
}
```

### 장점

- 한 곳 수정으로 전체 반영
- 테마 전환(다크 모드 등)에 유리
- 의미 있는 이름으로 가독성 향상

---

## 9. Flexbox & Grid

### Flexbox

**1차원** 레이아웃(행 또는 열)에 적합합니다.

- `display: flex`
- `justify-content`, `align-items`
- 아이템 정렬, 간격 조절

### Grid

**2차원** 레이아웃(행+열)에 적합합니다.

- `display: grid`
- `grid-template-columns`, `grid-template-rows`
- 카드 그리드, 복잡한 레이아웃
